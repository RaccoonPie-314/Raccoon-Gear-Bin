The module is a standard Supabase project rooted at `supabase/` with three parts: `config.toml` configures the local Supabase stack (Postgres 15 on port 54322, REST API on 54321, Studio on 54323, Auth with email provider, Storage with 50 MiB file limit, and analytics disabled); `migrations/` holds versioned SQL migrations that build the `public` schema — `20260922_000001_create_catalog_schema.sql` creates tables (`categories`, `category_translations`, `products`, `product_translations`, `product_images`, `admin_users`), indexes, and `handle_updated_at` triggers; `20260922000002_storage_and_rls.sql` enables Row Level Security on all tables and defines per-table policies that expose active/published data to everyone while restricting writes to authenticated admins (role-checked via `admin_users`), plus storage bucket policies for `product-images`; `20260922073136_remove_recursive_admin_users_policy.sql` adjusts admin policies. The `.temp/` directory stores runtime state (project ref, linked project, versions) used by the Supabase CLI. Dependency direction is strictly migration-driven: later migrations depend on earlier schema definitions.
