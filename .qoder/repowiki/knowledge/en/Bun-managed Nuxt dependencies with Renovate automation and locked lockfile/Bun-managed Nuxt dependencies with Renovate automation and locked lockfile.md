## System / Approach

This repository is a single-package Nuxt 3 application whose third-party JavaScript/TypeScript dependencies are managed by **Bun** (not npm/yarn/pnpm). The package manifest is `package.json`, the resolved dependency tree is pinned in `bun.lock` (lockfileVersion 1), and automated version updates are handled by **Renovate** via `renovate.json`.

There is no vendoring of JS source code — all packages are installed from the public npm registry at install/build time. No private registries, `npmrc`, `.npmrc`, or `GOPRIVATE`-style configuration files exist in the repo.

## Key Files

- `package.json` — declares the project (`"private": true`, `"type": "module"`) and the 12 direct runtime dependencies: `nuxt`, `@nuxt/ui`, `@nuxtjs/color-mode`, `@nuxtjs/i18n`, `@nuxtjs/supabase`, `@supabase/supabase-js`, `@tailwindcss/vite`, `tailwindcss`, `vue`, `vue-router`, and the `supabase` CLI.
- `bun.lock` — deterministic lockfile generated by Bun; it records exact versions and sha512 integrity hashes for every transitive dependency under the `packages` map.
- `renovate.json` — extends `github>nuxt/renovate-config-nuxt`, so Renovate applies the Nuxt team's recommended update policy to this repo.
- `.github/workflows/ci.yml` — CI step runs `bun install --frozen-lockfile`, which enforces that the committed lockfile matches the current `package.json`.
- `skills-lock.json` — locks two AI agent skills (`supabase`, `supabase-postgres-best-practices`) sourced from the `supabase/agent-skills` GitHub repo; each skill entry has a `computedHash` for integrity verification.

## Architecture & Conventions

- **Dependency declaration style**: All direct dependencies use caret ranges (`^x.y.z`). There are no fixed-pinned versions in `package.json`; pinning is delegated to `bun.lock`.
- **Install hook**: A `postinstall` script runs `nuxt prepare`, ensuring type generation and Nuxt internals are ready immediately after `bun install`.
- **Build scripts**: `build` → `nuxt build`, `dev` → `nuxt dev`, `generate` → `nuxt generate`, `preview` → `nuxt preview`. No custom dependency installation logic beyond Bun's default behavior.
- **Lockfile enforcement**: The CI workflow uses `bun install --frozen-lockfile`, which fails if `bun.lock` is out of sync with `package.json`. This makes the lockfile a hard invariant for CI.
- **Update strategy**: Renovate is configured to extend the official Nuxt Renovate preset (`github>nuxt/renovate-config-nuxt`); there are no custom rules overriding major/minor/patch policies in this file, so the preset governs branch naming, PR scheduling, and version bumping.
- **Agent skills as dependencies**: The `skills-lock.json` file pins two external Markdown-based "skills" from `supabase/agent-skills` on GitHub. Each skill has a `source`, `sourceType: "github"`, a `skillPath`, and a `computedHash` used to verify the fetched content hasn't changed — analogous to a lockfile for non-NPM assets.

## Conventions & Constraints

- **Package manager**: Bun is the sole declared package manager; the presence of `bun.lock` and the CI step `oven-sh/setup-bun@v2` + `bun install --frozen-lockfile` establish this convention.
- **Lockfile must be committed**: `--frozen-lockfile` in CI means any change to `package.json` requires a corresponding regenerated `bun.lock` — otherwise CI fails.
- **No vendored node_modules**: Dependencies are not checked in; they are resolved at install time from the public npm registry.
- **Private registry / auth**: None configured. No `.npmrc`, `package.json` `publishConfig.registry`, or environment variables for registry auth are present.
- **Version ranges**: Direct dependencies use `^` semver ranges in `package.json`; exact versions live only in `bun.lock`.
- **Renovate-driven updates**: Automated PRs for dependency updates are expected via Renovate using the Nuxt preset; manual major-version bumps should go through Renovate rather than ad-hoc edits.
- **Skills lockfile integrity**: `skills-lock.json` entries include a `computedHash` per skill, acting as an integrity check against the upstream GitHub source.
