The root is a single Nuxt 4 application whose `nuxt.config.ts` wires the two child domains together by registering shared modules (`@nuxtjs/supabase`, `@nuxtjs/i18n`, `@nuxtjs/color-mode`, `@nuxt/ui`) and declaring runtime configuration. The `supabase` block exposes both anon and service-role keys so the `frontend_app` can call Supabase REST/Postgres APIs that are governed by the `supabase_backend` Postgres schema, RLS policies, and storage rules — making the backend's security model the enforcement boundary for all data access from the SPA. Cross-child contracts are cookie-based: `raccoon-admin-auth` carries admin session state between the Nuxt app and Supabase Auth, while `raccoon-gear-bin-locale` persists the i18n locale declared in `i18n.config.ts` (en/km) across catalog and admin pages. Static branding assets under `public/` are served directly by Nuxt to both domains.
